# 0.4 图片素材验收记录

日期：2026-11-17（Asia/Shanghai）。范围见 Issue [#7](https://github.com/nkvic520/and-there-was/issues/7)。被测实现为本文件所在 0.4 分支；最终代码提交 SHA 和 Actions 结果记录在关联 PR。真实会话、图片模型响应、截图和密钥均不提交到公开仓库。

## 已实现

世界模式与素材来源独立：动态动画／静态漫画绘本 × AI 画图／素材与上传。DeepSeek 负责完整场景、脚本、规则和图片需求，Seedream 负责图片。SDK 4 用素材别名绘制 `sprite`，只向脚本暴露原有场景 SDK。图片原件、显示 PNG、来源、哈希及图片模型请求响应均持久化；原件可以下载。

上传默认原样使用，保留纸张背景，不自动改画。只有本次选中的上传图与明确参考图许可同时满足，才能发送给 Seedream；免费素材不发送给图片模型。内置 9 张 Kenney CC0 图片的来源及原包许可随仓库提供。

## 真实 DeepSeek + Seedream

模型：`deepseek-flash` 与 `doubao-seedream-5-5-261028`。使用本机 `.env` 配置。以下是本次测量，不是延迟保证。

| 场景 | 结果及耗时 |
| --- | --- |
| 单独请求透明狐狸 | Seedream 约 17.3 秒，原图 3.92 MB；检查了透明图片 |
| 角色图片 + 动态编排 | 约 19.6 秒提交，21 个节点、11 个动画节点、1 个点击绑定 |
| 只修改漂浮速度 | 约 6.7 秒提交，图片哈希和 Seedream 调用次数不变 |
| 完整水彩绘本 | 约 24.2 秒提交，1 张插画及应用文字，6 个节点、无动画和事件 |
| 上传验收图片 | 约 6.8 秒完成 DeepSeek 编排，有漂浮与点击；Seedream 调用次数为 0，原件保持不变 |
| 背景与角色分层的森林 | 收紧画面指导后约 37.5 秒提交；两张 Seedream 图片分别作为背景和角色，18 个节点 |
| Edge 页面完整提交与点击 | 首次 DeepSeek 输出无效 JSON，诊断保留且未显示候选。点击一次“再试一次”后成功：本地反馈约 48 ms，从本次重试到原画布首屏约 42.7 秒，背景/角色两张图片，点击改变状态 |

前六项计时从服务端提交开始至候选试跑和版本提交结束，不冒充浏览器首屏。最后一项在正在运行的生产应用中由 Edge 直接点击发送／重试计时。两次适配器初期联调曾发现素材别名不匹配，已通过更明确的 ID 清单、错误诊断和复用失败尝试中成功图片的机制修正；无效候选未提交。

真实会话通过服务器关闭／重开后的快照比较；实际图片也经过浏览器加载、点击与刷新检查。最终页面生成的森林在生产服务重启后，又用全新 Edge 上下文核对了完整快照、暂停画面像素、播放进度、轮次和图片任务数量，全部一致。上传验收使用测试图片，没有使用真实小朋友的私人作品。新图片是独立位图角色，当前动作是移动、缩放、旋转和关键帧反应，不代表完成骨骼或逐帧行走动画。

## 可复现操作

1. `npm ci`、`npm run dev`，打开 `http://127.0.0.1:5173/`。无密钥默认样例；输入「有一个球」仍走完整旧闭环。
2. 在“素材／我的作品”勾选图片，样例模式输入「使用选中的素材」。动态模式应持续活动且能点击，绘本模式应静止。也可上传 PNG/JPEG/WebP 后执行同一句样例。
3. 真实生成配置 DeepSeek 和 Seedream 后重启。选择 AI 画图，输入「森林里有一只可爱的小狐狸，萤火虫在它身边飞舞，点击它会跳一下」。等待提示后，同一画布显示场景；失败可重试。
4. 再输入仅修改速度的要求，核对 `/inspect/<worldId>` 中复用的图片哈希和图片任务数。选择“素材／我的作品”并上传图片时，不勾选 AI 参考图许可，确认没有图片模型调用。
5. 保存完整 `/w/<worldId>`。执行生产构建并用 `npm start` 运行，停止、重启，使用新浏览器上下文访问完整 URL；核对版本、状态、图片/原件哈希和生成记录数均不变。
