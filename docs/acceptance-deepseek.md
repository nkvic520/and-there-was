## 真实 DeepSeek 实测

使用本机 `.env` 的实际密钥调用官方 API，没有把密钥或会话产物提交到 Git。

1. 「要有光」得到可见光的协议和脚本。
2. 「碰三次出现一扇门」生成触碰事件与计数状态；第二次触碰后关闭并重开服务，快照完全相同；第三次触碰后 `tapCount=3`、`doorOpen=true`，运行结果包含门的绘图。
3. 要求新增必填 `themeColor=#ffc233`，模型生成的协议将其声明为必填，迁移后旧状态字段和值全部保留。

上述 API/QuickJS/SQLite 集成实测中，成功的光生成、规则生成和字段升级分别约 3.65s、3.95s、4.81s。第一项为一次失败后的修正尝试耗时，不包含先前失败请求；这些计时截至试跑提交，不是人工观察的首帧计时。

这不是“每次生成都会成功”的结论。实测出现过不合法 JSON、未绘制对象上的绑定、非法坐标及修改冻结 SDK 的脚本；它们被拦截并留档，原场景没有被覆盖。显式重试把错误和代码交给模型后，未绘制对象绑定问题修正成功。另一个手机旧世界的规则生成出现 JSON 失败，也保留了上一有效画面。
