# 「就有了」项目架构与需求说明

英文名 **And There Was…**

约 10 岁的孩子在 Windows 电脑或 Android 手机上打开一块黑色或白色的空画布。画布只有一个文本入口，孩子可以打字，也可以用系统输入法听写。提交「有一个球」，球就在眼前出现。提交「要有光」，一道光可能从上方落下，也可能从角落亮起。下一句话可以继续改变眼前的世界。

首版采用网页客户端和可自托管的服务端。客户端常驻画布和输入，服务器用提交的文本调用多模态模型并保存每轮产物。模型在游玩过程中实时生成或扩展这个世界的场景协议，并产出与之匹配的界面、素材和交互代码。桌面端、移动端和实体玩具可以复用宿主接口与记录格式，加载同一份世界版本。

## 首版产品需求

| 编号 | 需求 | 可观察结果 |
| :---: | --- | --- |
| **R1** | 空白起点 | 打开后只看到空画布和一个文本入口。实体键盘和系统输入法都能写入文字，听写后的文字可以编辑，确认后提交。 |
| **R2** | 开放表达 | 想说什么就说什么。模型结合本轮输入与当前场景决定表现。同一句话可以有不同的构图、出现位置和动画。 |
| **R3** | 场景在原处变化 | 提交后立即得到本地反馈。在同一画布里添加、修改、消除对象，或用鼠标和触屏与生成的物体互动。 |
| **R4** | 代码自动运行 | 模型生成可保存的脚本、界面描述和素材。通过验证与隔离试跑后，应用自动挂载该版本。 |
| **R5** | 完整留存 | 项目所有者能查看、导出和恢复提交的文本、模型输出、场景协议、源代码、素材和运行结果。听写与打字的归档格式相同，语音输入仅保存最终提交的文本。 |
| **R6** | 自部署与作品发布 | 服务可在部署者自己的服务器运行。项目所有者可以把一个已保存的世界版本发布为可玩的链接。 |
| **R7** | 场景协议实时生成 | 模型根据输入定义或扩展对象类型、状态字段、事件和行为绑定。新协议和配套代码校验通过后，在当前画布自动生效。 |
| **R8** | 失败后继续玩 | 生成超时或代码出错时，孩子可以继续玩最近可用的场景，在输入区重试或修改原句。可以撤销最近一次生效的生成变更。 |

## 首版场景

先支持 2D，主要验收设备是 Windows 电脑和 Android 手机。Windows 用实体键盘和鼠标，Android 用系统键盘和触屏。浏览器端优先验证 Windows 的 Edge 或 Chrome 及 Android 的 Chrome，实测中文输入法组合输入、Android 软键盘弹起和触摸命中。玩法由孩子临时发明，例如让一个光点在被碰到时变成两个。管理、导出和发布放在独立入口。

### 文本与系统听写

网页使用标准文本控件。应用及服务端的输入接口只接收最终提交的文本，听写由操作系统或输入法负责。孩子先看到识别结果，可以修正后再发送。输入法处于选字状态时，回车用于确认候选字，显式发送提交整句。

为满足语音留在设备上的要求，试玩时使用已在目标设备和所用语言上验证过的离线听写。Windows 的 `Win+H` 听写使用在线识别，Android 的听写处理方式取决于所用输入法和功能。设备可直接用键盘输入文字。 [Microsoft Windows 听写说明](https://support.microsoft.com/en-us/accessibility/windows/use-voice-typing-to-talk-instead-of-type-on-your-pc) · [Gboard 高级听写说明](https://support.google.com/gboard/answer/11197787)

## 系统架构与运行顺序

**画布和输入 → 会话服务 → 生成场景协议、代码与素材 → 保存候选版本 → 隔离试跑 → 场景生效**

| 组件 | 职责 |
| --- | --- |
| **客户端宿主** | 持有画布、文本输入和已生效的场景状态。将提交的文字送入会话服务，依据当前场景协议转交鼠标或触摸事件，渲染已通过校验的变更。提供等待和重试反馈。 |
| **会话 API** | 接收并归档每轮输入，按世界排队调用模型，管理基线版本、产物和发布权限。通过事件流推送生成进度和版本状态。 |
| **模型与素材适配器** | 将提交的文本和世界上下文送入模型。模型返回场景协议或协议补丁，配套脚本与图像、音效等输出素材可随包返回或按需生成。 |
| **隔离执行器** | 试跑候选脚本，按候选协议校验事件和状态。脚本通过场景 SDK 提交绘制、动画与交互操作。 |
| **版本与文件存储** | 保存提交文本、模型输出、每轮事件、协议定义、世界快照和运行包。保留内容哈希和依赖关系，以便恢复和发布。 |

### 每轮处理顺序

**1  接收输入** 客户端先显示本地反馈。服务端分配轮次 ID，保存用户提交的文本原文，记录当前世界版本。

**2  生成候选产物** 模型读入本轮内容、当前场景协议、世界快照和 SDK 能力说明。它可沿用当前协议，也可为这轮请求生成或扩展类型、状态、事件和行为绑定，同时交付可执行模块与素材清单。服务端连续保存可见的原始响应和素材生成进度。

**3  验证并保存版本** 持久化候选包，校验文件、协议定义、事件绑定和资源引用。客户端在隔离环境试跑脚本，并验证迁移后的状态。试跑成功且基线有效时，服务端一次提交协议、代码和状态，再通知客户端生效。

**4  在画布上演出** 客户端按对象应用这次变更并播放入场动画。耗时素材可以后续作为补丁更新对应对象。前台允许继续输入，生成按轮次排队。

### 接口约定

客户端用 HTTPS 提交文本轮次。服务端用 SSE（服务器发送事件）推送轮次状态和版本 ID。事件序号与轮次落库，重连可补取遗漏事件。画面只消费已保存的版本和可读资产。

[WHATWG 服务器发送事件规范](https://html.spec.whatwg.org/multipage/server-sent-events.html)

## 生成代码与运行内核

### 场景协议实时生成

**宿主接口** 宿主提供加载模块、绘制图形、播放动画与声音，以及触摸和计时等通用能力。模块包格式与 SDK 接口有自己的版本，可供各端实现。

**世界的场景协议** 从空世界开始，模型根据孩子的表达定义对象、属性、状态和自定义事件，并将事件绑定到生成的处理代码。首版可用受限的 JSON Schema 描述状态和事件参数，由宿主校验轮次提交的协议及其数据。计分和关卡可以由模型定义为这个世界的状态和事件，规则写在同一轮生成的脚本里。 [JSON Schema 文档](https://json-schema.org/learn/getting-started-step-by-step)

**例子** 孩子先说「要有光」，画布上出现一团光。再说「碰这团光三次，就出现一扇门」，模型为这团光新增 `tapCount` 状态和 `light.touched` 事件，把宿主的触摸输入绑定到该事件，再生成累计次数和显示门的代码。第三次触摸时，宿主直接调用已挂载的代码。

### 生成产物格式

每个生成模块随包保存场景协议定义或补丁、入口脚本、界面描述以及素材文件或引用。清单记录模块 ID、基线世界版本、场景协议版本、SDK 版本和文件哈希。服务端分配 ID 和版本。首版接受 JavaScript 源码与结构化界面描述，脚本通过 SDK 生成贴图、图形、交互控件和动画。

模块的 `mount` 入口生成初始场景，`onEvent` 处理当前协议定义的事件。旧状态需要转换时，候选模块提供 `migrate`。跨轮需要保留的数据由 SDK 写入可序列化的模块状态，随世界版本恢复。

### 执行环境

**最小权限** 首版可在专用 Web Worker 内嵌入 QuickJS（WASM）。仅向生成代码提供场景 SDK，供其绘制、播放已授权的素材、订阅事件和读写模块状态。身份凭证、网络和文件操作由宿主与服务端持有。

**资源与回退** 给每次脚本调用设置时间、内存和输出操作数上限。宿主验证返回的动作再应用，超时则终止相应执行器。候选代码失败时记录失败版本，并继续显示上一个可用场景。

**独立界面** 以后需要运行完整的 HTML/CSS 页面时，可使用独立来源的沙箱 iframe 作为受限画布图层，通过校验消息与宿主通信。生成内容与服务端应用进程使用各自的执行环境。

[QuickJS 资源控制](https://bellard.org/quickjs/quickjs.html#Memory-handling) · [QuickJS 的 WASM 封装](https://github.com/justjake/quickjs-emscripten) · [WHATWG iframe 沙箱](https://html.spec.whatwg.org/multipage/iframe-embed-object.html#attr-iframe-sandbox)

### 场景一致性

**版本切换** 宿主维护对象 ID、当前生效的场景协议、模块和状态。兼容的变更可以沿用旧状态。需要转换时，先在隔离环境执行迁移，再用候选协议校验状态。提交时核对基线世界版本和状态修订号，通过后一起启用新协议、处理代码、事件绑定和状态。若期间发生触摸等状态变更，用最新快照重新试跑。失败时保留最近可用版本。

**重复提交与晚到结果** 网络重发同一提交时返回已有轮次状态。孩子主动重试已失败的轮次时，在同一轮次下记录一次新的生成尝试。晚到的模型或素材结果必须匹配有效的尝试、世界和目标对象版本。

**可复现的变化** 随机位置、路径、节奏可在运行时抽取，记录实际取值。触摸输入在本地执行，事件和变更写入浏览器持久队列，重连可补传。下一轮模型读取同步后的最新场景。

### 失败后继续玩

**输入有误** 孩子可以在提交前编辑听写文本。提交后需要改一句时，可以把原句放回输入框，改好再发。

**生成或执行失败** 超时、校验失败和脚本异常由宿主处理。宿主保留失败的候选产物和诊断，画布继续运行最近可用的场景。输入区给出简短提示并提供重试。已挂载脚本的单次互动失败时，撤销该次动作的暂存变更，保留执行前状态并记录错误。

**撤销** 输入区提供撤销最近一次生效生成的入口。宿主恢复上一世界版本的协议、代码和状态，并把撤销写成可追溯的版本事件。

## 完整输入输出与版本恢复

以世界 ID 和轮次 ID 串起提交文本、执行和输出。数据库保存文本、事件、版本与引用关系，生成的代码快照及图像、合成音效等素材作为文件持久化。文件校验完成后，数据库再提交对应版本的引用。

### 每轮保存的记录

| 记录 | 保存内容 |
| --- | --- |
| **提交文本** | 每次实际提交的完整文本和提交时间。键入与系统听写所得的文本按同一格式保存，鼠标与触摸事件随运行结果记录。 |
| **模型请求和响应** | 实际发出的消息正文、上下文及输入引用，模型标识、参数、提示词和协议版本。接口可见的原始响应与流式片段，含中止或失败的部分结果。 |
| **生成产物** | 每次尝试返回的协议定义或补丁、源代码、界面描述、素材原件和产物清单。通过验证后另保存完整的生效协议、实际运行包及其依赖、文件哈希和入口。 |
| **运行结果** | 执行时间线、协议校验和迁移结果、运行错误、已应用的事件与随机取值。重试、取消和素材晚到均有记录。事件记录带有执行时的世界版本和协议版本。 |
| **世界版本** | 生效版本及上一版本、对应的协议快照、已挂载模块、可序列化的对象与交互状态、素材引用和运行时版本。 |

### 恢复回放与导出

**恢复继续玩** 读取世界快照及对应的场景协议、运行包和素材。回放后续事件时，按事件保存的版本加载当时的协议和处理代码。

**导出完整项目** 归档包带可读的记录清单、提交文本、模型输出、各版协议定义、源代码和生成素材。首版回放按当时的事件与状态演出。

**儿童记录的访问** 会话档案默认私有，由自部署实例的项目所有者管理读取、导出、保留期限和删除。发布的作品包按选定版本引用运行所需代码与素材。模型凭证存于服务端配置。

## 客户端选型与服务运行

网页、桌面应用、原生移动端和带屏实体玩具都能实现这套交互。首版选网页，Windows 电脑和 Android 手机可以通过同一个自部署地址试玩。各端通过兼容的宿主接口读取每个世界的协议和运行包。

| 客户端 | 实现方式 | 适用场景或代价 |
| --- | --- | --- |
| **网页** | TypeScript + Vite。PixiJS 渲染画布，HTML 文本输入，脚本隔离执行。 | 适合首轮试玩与自部署。在 Windows 和 Android 实测输入法、鼠标或触摸及动效。 |
| **桌面应用** | 用 Tauri 把网页客户端装进 WebView，复用模块加载、绘制和服务器接口。 | 适合独立安装、全屏体验、本地存储或硬件接入。宿主按需提供系统能力。 |
| **原生移动端** | 原生宿主实现同一套通用接口，在受限脚本运行时加载生成的协议与代码。也可用隔离的 WebView。 | 适合需要系统界面或触觉反馈的版本。动态执行与儿童数据按发行渠道核对。 |
| **引擎或实体玩具** | 例如用 Godot 原生客户端渲染场景指令，运行于平板或带屏触摸设备。 | 适合真实 3D、传感器和按钮。需适配渲染与输入，离线模型另做算力与延迟验证。 |

发行移动应用时，Apple 以 2.5.2 约束动态代码，并在 4.7 对 HTML5 和 JavaScript 小游戏等形式规定条件。Google Play 对下载原生可执行代码和解释执行的脚本有不同规定。实际选型应结合生成模块的能力和发行方式。

[Apple App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/#software-requirements) · [Google Play Device and Network Abuse](https://support.google.com/googleplay/android-developer/answer/16559646)

### 服务部署与作品发布

**实例部署** 首版由同一个 Node.js 应用提供前端静态文件和 `/api/`，统一从一个 HTTPS 地址访问。部署者配置模型地址和凭证，SQLite 和内容文件放进同一实例的持久卷，按同一归档点备份及恢复。扩展到多台服务时可将数据库和文件迁至 PostgreSQL 与对象存储。

**版本发布** 选择已通过试跑的世界版本，锁定其场景、协议、运行包和素材，生成按权限访问的播放链接。链接始终对应所选版本。

[SQLite 在线备份](https://sqlite.org/backup.html)

## 首版验收与开发顺序

第一段可玩的体验从空画布开始，支持一句话生成对象和下一句话修改对象。分别在 Windows 和 Android 验证文本输入、现场生成和鼠标或触屏互动，同时检查服务器上保存的实际产物。

| 需求 | 验收操作 | 通过条件 |
| :---: | --- | --- |
| **R1** | 在 Windows 和 Android 验证键盘输入，使用已验证的离线听写功能测试语音转文字。 | 同一文本框可编辑两种方式产生的文字。回车选字时只确认候选字，明确发送时才提交。提交轮次的请求只包含文本和相应元数据。 |
| **R2** | 输入「有一个球」「要有光」「黑夜打了个哈欠」。重复一条输入。 | 主要变化可辨认，抽象句也有可理解的画面回应。独立运行能得到多种入场方式。 |
| **R3、R4** | 输入「碰这团光就分成两个」，用鼠标或触屏触发。 | 生成的交互自动挂载，点击和触摸可在本地执行。画布和输入连续可用，可查到实际运行的脚本版本。 |
| **R4** | 测试脚本超时、访问网络，以及过期结果和重复提交。 | 越权调用和超时被拦截，错误记录可查。网络重发返回已有轮次状态。只有基线有效的产物可以生效。 |
| **R5** | 查看打字和听写的记录，导出项目，在服务重启后重新打开。 | 两类输入的归档都只含最终提交的文字。模型请求与响应、协议、源代码、素材及运行日志可逐轮核对，恢复后能执行已生成的互动。 |
| **R6** | 启动自部署实例，发布一个已保存的世界版本。 | 在目标设备打开实例地址即可试玩。访问控制覆盖播放链接与私有档案，备份恢复后内容仍可用。 |
| **R7** | 在已经出现的光上加规则「碰三次出现一扇门」。随后给已有触碰次数的世界新增一个必填状态字段。 | 本轮生成的协议含新状态和事件定义，配套代码在当前画布自动生效，第三次触碰显示门。升级后已有次数被保留，新字段通过迁移初始化。若迁移校验失败，原有互动仍可玩。 |
| **R8** | 模拟误听、生成超时、运行错误和撤销。 | 孩子可改原句或重新尝试，已生效的场景继续可玩。撤销恢复上一世界版本并留下记录。 |

### 输出质量与性能

渲染器提供统一的光晕、笔触和动效，保证主体落定后可见，并限制亮度变化与音量。测试记录提交到本地反馈、提交到首个可辨认变化的时间。用目标设备反复生成并试玩，观察孩子理解了什么、是否愿意触碰或接着说。延迟目标以所选模型和设备的实测为准。
